# Admin and master functionality audit

Audit date: 6 September 2026. Scope: every entry in `adminRoutes` in `src/App.jsx`, `/master`, admin login/navigation and the shared product/media editors. Existing user work and `.env` are preserved. No production data, live social messages/posts or real payments were changed.

## What the evidence means

- **UI workflow** means the actual React screen/components were exercised with controlled API responses, including the stated error/concurrency cases. It establishes the UI-to-API contract, not live provider connectivity.
- **API workflow** means the actual Express middleware/controllers/Mongoose persistence ran against isolated MongoDB. See [the backend matrix](audit-backend-matrix.md) for route-by-route execution and permission evidence. Social/Gemini/storage network responses are controlled fixtures.
- **Browser sweep** means the built application rendered and fetched actual isolated API data at mobile and desktop widths. It does not imply every button on that screen was exercised. The parent audit records its connected multi-page actions and screenshots separately in `.tmp/full-app-audit/`.
- **Source trace** means the listed action was traced from handler to route/response contract. Unexercised combinations remain unproven; a source trace is not labeled end-to-end.

Final focused admin evidence: 17 suites / 130 tests passed together, plus 2 poster workflow tests run separately. Scoped ESLint passes for all admin source and test files. Draft/social/reel API regression run: 27 tests passed. Expanded Social studio API suite: 22 tests passed, including posts/history/video/delete, webhook verification, confirmed-failure publish retry and an attachment-persistence regression. The parent audit supplies the final whole-app frontend/backend/build totals after consolidation.

## Concrete external limits

- `.env` is untouched. Provider setup cannot be inferred from a button existing or a successful fixture test.
- Production MongoDB reachability, Atlas network/DNS and deployed environment configuration require a reachable database. Isolated API tests use a disposable local replica set.
- Real OTP requires the configured SMS/email provider to deliver messages. Demo OTP or controlled test delivery does not establish production SMS delivery.
- Social OAuth requires Meta app credentials, valid public callback/webhook URLs, approved permissions, a Facebook Page and the appropriate linked professional Instagram account. Root readiness check found the app/callback setup incomplete. Meta messaging windows and account capabilities remain enforced. No live customer messages or posts were sent.
- Smart photo/reel fill requires a working Gemini credential/quota/model and clear source media. The tests verify error propagation/recovery, descriptive field application and manual commercial-field controls; they do not promise accurate classification for every frame or a fixed daily allowance.
- Reel extraction needs configured durable media storage plus the bundled local FFmpeg path or a reachable authenticated video worker. Remote processing/storage outages are reported; local test media is not a production storage proof.
- Payment verification and provider webhooks are implemented and require valid provider configuration; real bank settlement was not tested. Admin `Refunded` controls record internal status; they do not initiate a gateway refund. Incoming refund webhooks are handled separately.
- Shipping currently reports `liveBooking: false` and `trackingLookup: false` even when credentials exist. Manual shipment/AWB/tracking URL workflows are implemented; automatic courier booking and tracking lookup are implementation gaps.
- Notifications currently poll in-app every 30 seconds. Background/OS push is an implementation gap. The subscriber screen records/searches email addresses; it does not provide campaign sending.

No source trace, fixture, route sweep or passing test count is presented as a guarantee that every external integration is already connected.
