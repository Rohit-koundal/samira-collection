# Customer and seller functionality audit

Audit date: 6 September 2026. Scope is the actual registered customer and seller routes in `src/App.jsx`, including their shared navigation, API state, responsive views and mutations. Changes preserve existing local work and do not modify `.env` or use production accounts/data.

## Evidence and boundaries

- Focused regression run: 12 suites, 78 tests passed on the customer/seller recovery changes. Additional final footer/seller-route tests are recorded in the parent audit's final frontend test run.
- Existing order, wishlist, cart, notification, login, gallery, receipt and seller operation tests remain part of the full frontend suite. The matrix names the relevant files; naming an existing test is not a claim that every possible input combination was exercised.
- The parent audit ran the actual built application at mobile and desktop sizes against an isolated backend, with real app authentication and seeded fixture data. Artifacts are in `.tmp/full-app-audit/`, including `browser-customer-390-1440.json` and route screenshots. The parent audit also exercised COD ordering, PDF invoice generation, cancellation, return requests, notification actions and a simulated online-payment verification outage/retry.
- External SMS/email delivery, Razorpay bank settlement, Meta OAuth/DM delivery/publishing, courier pickup and AI provider availability/quotas require their configured providers. Automated fixtures verify application behavior; they do not prove those external services are connected. OS/background push is not implemented: notifications use in-app polling, badges and banners while the app is open. Automatic courier booking and tracking synchronization are also not implemented; the app supports manual real-AWB entry and tracking links. No live messages, social posts, payments or account deletions were sent by this audit.

## External and operational limitations

The application can expose useful failure states without making an unavailable provider operational. Demo setup must use a reachable database and the intended OTP/payment modes. Meta tools require suitable accounts, permissions and valid OAuth configuration; AI assist requires a configured provider and available quota. Shipping currently supports manual courier booking outside the app, real-AWB entry and saved tracking links; `shippingProvider.js` reports live booking and tracking synchronization as disabled even when credentials are present. In-app alerts are available, but OS/background push is not implemented. Policies, contact details, inventory and commercial settings are business-owned data and must be populated accurately. This audit did not replace existing `.env` values or modify real inventory.
